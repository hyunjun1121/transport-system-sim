# 기술 설명 초안

작성일: 2026-05-13

## 1. 시스템 개념

본 시스템은 공개 교통망과 시뮬레이션 AI를 결합해 비상 수송 대안을 비교하는 의사결정 지원 프로토타입이다. 핵심은 "AI가 실제 명령을 자동 작성"하는 것이 아니라, 동일한 조건에서 여러 수송 정책을 반복 실험하고 결과를 사람이 검토하기 쉬운 근거 자료로 바꾸는 것이다.

## 2. 데이터 계층

- 공개 도로망과 철도 접근 정보를 그래프 구조로 변환한다.
- 출발·환승·도착 지점은 실제 시설 좌표가 아니라 권역 라벨로 일반화한다.
- 가정값과 공개자료를 분리해, 출처가 없는 값은 시뮬레이션 파라미터로 표시한다.

## 3. 시뮬레이션 계층

- 도로 링크에는 기본 이동시간, 용량, 장애 확률 또는 장애 강도를 둔다.
- 철도 구간에는 이동시간, headway, 수송 용량을 둔다.
- 차량은 출발 간격, 회차 시간, 탑승 용량, fleet size 제약을 갖는다.
- 인원 도착 지연과 링크 장애를 반복 샘플링해 대안별 결과 분포를 비교한다.

## 4. 대안 비교 계층

비교 대안은 다음 두 축을 기본으로 한다.

- 버스 단독 수송: 도로망만 사용하는 대안
- 철도-버스 복합 수송: 도로 접근, 철도 이동, 말단 도로 이동을 결합하는 대안

출력 KPI는 완료시간, 성공률, 미수송 인원, 도로 차량 서비스 시간, 철도 서비스 시간, passenger travel minutes 등으로 구성한다.

## 5. AI 활용 방식

AI 활용은 다음 범위로 제한한다.

- 대안별 결과 요약
- 병목 구간과 취약 파라미터 설명
- 민감도 분석 결과의 자연어 요약
- 보고서 초안과 질의응답 보조

AI가 직접 실제 작전 명령, 세부 배차표, 실제 경로 지시를 생성하지 않는다. 핵심 판단 근거는 재현 가능한 시뮬레이션 산출물과 사람이 검토 가능한 evidence boundary에 둔다.

## 6. 웹 데모 계층

웹 데모는 Vite/React/Leaflet 기반으로 구성된다.

- 지도 화면: 서울/수서권, 수서 철도 접근점, 평택지제 환승권, 평택 지원 권역을 표시한다.
- 데이터 화면: `phase1_results.csv` 샘플을 표와 KPI 카드로 표시한다.
- 리뷰 화면: formal acceptance와 evidence boundary가 아직 닫히지 않았음을 표시한다.

웹 데모는 경연대회 보고서에 들어갈 설명 화면이며, 실제 운용 시스템이 아니다.

## 7. 검증 계획

- `npm run lint`, `npm run build`로 웹 데모 정적 검증
- 브라우저에서 지도 타일, 라벨, route layer, 데이터 표 확인
- 데스크톱/모바일 스크린샷 캡처
- 보고서 문구와 스크린샷 불일치 점검
- 금지 표현과 과장 표현 제거
