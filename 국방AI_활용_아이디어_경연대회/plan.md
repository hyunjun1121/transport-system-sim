# 국방 AI 활용 아이디어 경연대회 보고서 작성 계획

작성 기준일: 2026-05-13

## 1. 작성 목표

본 계획서는 경연대회 제출용 기획서 또는 보고서 초안을 작성하기 위한 작업 순서, 하위 에이전트 역할, 산출물 인수 조건, 검증 절차를 정의한다. 보고서는 다음 하나의 시나리오만 중심으로 구성한다.

> 서울/수서권 집결지와 철도 환승 축에서 평택지제역 및 평택 지원 권역으로 향하는 공공데이터 기반 비상 수송 의사결정 지원 시뮬레이션

보고서의 목적은 특정 경로를 지시하거나 실제 수송 명령을 작성하는 것이 아니다. 보고서는 공개 또는 공개 가능 데이터를 바탕으로 여러 수송 대안의 취약점, 지연 위험, 병목 조건, 정책 대안을 비교하는 비작전적 의사결정 지원 아이디어를 설명해야 한다.

## 2. 고정 시나리오 범위

보고서에는 정확히 하나의 시나리오만 사용한다.

- 출발 축: 서울/수서권 집결 및 철도 환승 접근 축
- 도착 축: 평택지제역 및 평택 지원 권역
- 수송 관점: 버스 단독 수송, 철도-버스 복합 수송, 예비 또는 분산 수송 정책을 비교하는 의사결정 지원
- 데이터 관점: 공개 교통망, 공개 철도역 또는 시간표 성격의 정보, 공개 도로망, 공개 행정구역 또는 시설 주변 지리 정보, 내부 임의 가정값을 분리 표기
- 분석 관점: 완료시간, 미수송 인원, 병목 구간, 지연 위험, 정책 민감도, 대안별 취약 조건

다음 내용은 보고서에 포함하지 않는다.

- 실제 출동 명령, 배차 명령, 작전 명령 또는 배치 지침
- 실제 운용 가능한 세부 시각표, 차량 대수, 동선, 집결 절차
- 특정 부대, 시설, 경계 위치, 보안 민감 정보
- 최종 검증 완료, 현장 적용 가능성 보장, 작전 효용 보장 표현
- 현재 프로젝트의 감사 또는 수용 보조 자료를 최종 승인 증거처럼 표현하는 문장

## 3. 핵심 메시지

보고서의 중심 문장은 다음 취지로 유지한다.

> 본 아이디어는 공공데이터와 시뮬레이션 AI를 활용해 비상 수송 대안을 사전에 비교하고, 지휘관과 참모가 제한된 시간 안에 병목과 실패 위험을 파악하도록 돕는 비작전적 의사결정 지원 체계이다.

강조할 차별점은 다음과 같다.

- 단일 최단 경로 추천이 아니라, 불확실성 아래 여러 수송 대안을 반복 비교한다.
- 생성형 AI 답변보다 재현 가능한 시뮬레이션, 최적화, 민감도 분석, 결과 설명을 전면에 둔다.
- 공공데이터 기반으로 시작하되, 군 내부 자료는 단계적·비식별·폐쇄망 방식으로 연계하는 구조를 제안한다.
- 결과는 명령이 아니라 참모 검토용 위험 지도, 대안 비교표, 병목 요약, 근거 로그로 제시한다.

## 4. 작업 원칙

1. 시나리오를 먼저 동결한 뒤 보고서 목차를 확정한다.
2. 공식 출처와 공공데이터 근거를 먼저 확보한 뒤 구체 문장으로 확장한다.
3. 웹 데모 지도, 레이블, Vercel 배포 URL이 준비된 뒤에만 스크린샷을 삽입한다.
4. 스크린샷과 URL이 확정된 뒤에만 데모 참조 문단을 최종 작성한다.
5. 주장 안전성 검토가 끝난 뒤에만 최종 제출본으로 간주한다.
6. 모든 산출물은 비작전성, 공개자료 기반, 검증 전 한계, 보안 민감성 회피를 명시한다.

## 5. gpt-5.5 high 하위 에이전트 실행 모델

하위 에이전트는 `gpt-5.5 high` 수준의 추론 모델을 가정하여 운영한다. 각 에이전트는 독립적으로 산출물을 만들되, 선행 산출물이 없는 상태에서 후속 문단을 확정하지 않는다.

### 5.2 의존성 순서

아래 순서는 반드시 지킨다.

1. `scenario_freeze.md` 작성
2. `source_evidence_matrix.md` 작성
3. `report_outline.md` 작성
4. `technical_sections.md` 작성
5. `demo_map_spec.md` 작성
6. 웹 데모 구현 및 Vercel URL 확정
7. 스크린샷 캡처 및 `screenshot_manifest.md` 작성
8. `demo_reference_paragraphs.md` 작성
9. `claim_safety_review.md` 작성
10. `final_report_draft.md` 통합
11. 최종 제출 전 검증 체크리스트 수행

특히 다음 의존성은 예외 없이 적용한다.

- 시나리오 동결과 공식 출처 근거가 보고서 목차보다 먼저다.
- 웹 데모 지도, 지도 라벨, Vercel URL이 스크린샷 삽입보다 먼저다.
- 스크린샷과 URL이 데모 참조 문단보다 먼저다.
- 주장 안전성 검토가 최종 제출보다 먼저다.

### 5.2.1 Sub-Agent Dependency DAG

보고서 작업은 웹 데모 산출물을 downstream evidence로 사용하므로, 보고서
에이전트만 독립적으로 완료 처리하지 않는다. 전체 의존성 그래프는 다음과
같다.

```text
시나리오 동결 에이전트
  -> 공식 출처·근거 에이전트
  -> 보고서 구조 에이전트
  -> 기술 설명 에이전트
  -> 웹 데모 에이전트
  -> 스크린샷 에이전트
  -> 데모 문단 에이전트
  -> 주장 안전성 검토 에이전트
  -> 최종 통합 에이전트

시나리오 동결 에이전트
  -> 웹 데모 에이전트

공식 출처·근거 에이전트
  -> 웹 데모 에이전트
  -> 주장 안전성 검토 에이전트

웹 데모 에이전트
  -> 스크린샷 에이전트
  -> 데모 문단 에이전트

스크린샷 에이전트
  -> 최종 통합 에이전트
```

Critical path는 `시나리오 동결 -> 공식 출처·근거 -> 웹 데모 구현/배포 ->
스크린샷 -> 데모 문단 -> 주장 안전성 검토 -> 최종 통합`이다. 보고서
구조와 기술 설명은 공식 출처·근거가 정리된 뒤 병렬 초안 작성이 가능하지만,
데모 문단과 최종 통합은 스크린샷과 URL을 입력으로 받은 뒤에만 확정한다.

병렬 가능한 작업은 다음으로 제한한다.

- 시나리오 동결 이후 공식 출처·근거 에이전트와 웹 데모 에이전트의
  화면 사양 초안 작성은 병렬 가능하다.
- 공식 출처·근거 행렬이 완성된 뒤 보고서 구조 에이전트와 기술 설명
  에이전트는 병렬로 초안을 작성할 수 있다.
- 웹 데모가 구현되었지만 배포 URL이 아직 없을 때, 주장 안전성 검토
  에이전트는 텍스트 초안 사전 검토를 할 수 있다.
- 최종 통합 에이전트는 스크린샷, URL, 데모 문단, 주장 안전성 검토 결과가
  모두 모이기 전에는 제출본을 완료 처리하지 않는다.

동기화 gate는 다음 다섯 지점이다.

1. Scenario gate: 하나의 서울/수서-평택지제-평택 지원 권역 시나리오만
   남아 있음.
2. Evidence gate: 공식 출처, 공개자료, 내부 가정값, 보류값이 분리됨.
3. Demo gate: 웹 데모 lint/build/browser 검증과 URL 확정이 끝남.
4. Screenshot gate: 확정 화면에서 캡처한 파일과 매니페스트가 존재함.
5. Submission gate: 주장 안전성 검토가 반영되고 최종 문서·URL·스크린샷
   참조가 서로 일치함.

### 5.3 web demo 계획과의 교차 의존성

보고서 계획은 `web_demo/plan.md`의 산출물을 downstream 입력으로 받는다.
따라서 보고서 작성 에이전트는 웹 데모가 확정되기 전에는 데모 관련 주장을
완성하지 않는다.

교차 의존성은 다음과 같이 관리한다.

| 선행 산출물 | 담당 계획 | 후행 산출물 | 후행 담당 | 고정 규칙 |
|---|---|---|---|---|
| 시나리오 동결 메모 | 양쪽 공통 | 보고서 목차, 지도 라벨 | 보고서 구조/웹 데모 에이전트 | 시나리오명과 권역 표현은 하나만 사용 |
| 공식 출처·근거 행렬 | 보고서 계획 | 지도 라벨, 캡션 근거 | 웹 데모/스크린샷 에이전트 | 출처 없는 값은 예시 가정으로만 표기 |
| 지도·KPI·주의 문구 구현 | web demo 계획 | 스크린샷 | 스크린샷 에이전트 | lint/build/browser 확인 전 캡처 금지 |
| Vercel URL 또는 검증된 로컬 preview | web demo 계획 | 데모 참조 문단 | 데모 문단 에이전트 | URL 또는 캡처 위치 없이 완료 문장 금지 |
| 스크린샷 매니페스트 | web demo 계획 | 보고서 그림 캡션 | 데모 문단/최종 통합 에이전트 | 화면에 없는 기능은 본문에 쓰지 않음 |
| 주장 안전성 리뷰 | 보고서 계획 | 제출본 | 최종 통합 에이전트 | 실제 작전 지시·성능 보장·최종 승인 표현 제거 |

## 6. 하위 에이전트별 세부 지시

### 6.1 시나리오 동결 에이전트

목표는 보고서가 하나의 시나리오에서 벗어나지 않도록 잠금 기준을 만드는 것이다.

필수 결정 사항:

- 명칭: 서울/수서-평택지제 비상 수송 의사결정 지원 시나리오
- 공간 표현: 서울/수서권, 철도 환승 축, 평택지제역, 평택 지원 권역처럼 넓은 권역 단위로 표기
- 금지 표현: 실제 집결지, 세부 동선, 세부 배차표, 작전계획, 실시간 통제, 자동 명령
- 허용 표현: 모의실험, 비교, 사전 검토, 의사결정 지원, 공개자료 기반, 비작전 예시

인수 조건:

- 시나리오가 하나만 남아 있어야 한다.
- 서울/수서와 평택지제/평택 지원 권역 외 다른 실증 축을 추가하지 않아야 한다.
- 세부 작전 경로처럼 읽히는 문장이 없어야 한다.

### 6.2 공식 출처·근거 에이전트

목표는 보고서에 쓸 수 있는 출처 후보와 아직 검증되지 않은 가정값을 분리하는 것이다.

근거 분류:

- 공모 공식 근거: 공모 주제, 평가 항목, 제출 형식, 일정
- 공공 교통망 근거: 도로망, 철도역, 행정구역, 지도 배경
- 시뮬레이션 근거: 프로젝트 내부 모델, 테스트, 산출물 구조
- 가정값: 차량 수, 수요 규모, 지연 분포, 장애 강도, 정책 파라미터
- 보류값: 공식 확인 전 수치, 민감 가능성이 있는 위치, 실제 운용과 연결될 수 있는 정보

작성 방식:

- 출처명, URL 또는 파일 경로, 확인일, 사용 가능한 문장, 한계, 보고서 반영 위치를 표로 정리한다.
- 출처가 확인되지 않은 값은 보고서 본문에서 "예시 가정", "시뮬레이션 설정값", "검토용 파라미터"로만 쓴다.
- 공식 출처가 없는 내용은 수치처럼 단정하지 않는다.

인수 조건:

- 모든 본문 주장에 출처, 내부 산출물, 또는 가정값 표기가 연결되어야 한다.
- 공공데이터와 내부 가정이 한 문장 안에서 섞일 경우 구분 문구가 있어야 한다.

### 6.3 보고서 구조 에이전트

목표는 제출 양식 안에서 평가 기준에 맞는 목차를 구성하는 것이다.

권장 5쪽 구성:

1. 아이디어명, 분야 선택, 제안 배경 및 목적
2. 아이디어 요약, 단일 시나리오, 데이터 입력 구조
3. AI·시뮬레이션 구조, 대안 비교 방식, 결과 예시
4. 차별성, 실현 가능성, 데이터 보안 및 비작전 안전장치
5. 적용 효과성, 추진 전략, 한계 및 검증 계획

본문의 중심 흐름:

- 문제: 비상 수송 판단은 빠르지만 단일 경로 확정으로는 불확실성을 다루기 어렵다.
- 제안: 공공데이터 기반 시뮬레이션 AI가 여러 수송 대안을 반복 비교한다.
- 시나리오: 서울/수서권에서 평택지제·평택 지원 권역까지의 비작전 예시.
- 방법: 도로·철도망, 수요, 장애, 정책을 입력하고 KPI를 산출한다.
- 결과: 병목, 지연 위험, 미수송 위험, 대안별 취약 조건을 표와 지도에 표시한다.
- 안전: 실제 운용 명령이 아니라 사전 검토와 훈련용 의사결정 지원이다.

인수 조건:

- 다른 시나리오가 목차나 예시로 추가되지 않아야 한다.
- 데모 관련 문단은 URL과 스크린샷 확정 전에는 자리표시자로만 둔다.

### 6.4 기술 설명 에이전트

목표는 구현 가능성과 AI 활용 방식을 과장 없이 설명하는 것이다.

포함할 기술 요소:

- 공공 교통망을 그래프로 변환하는 데이터 계층
- 도로 혼잡, 링크 장애, 지연, 차량 회차, 환승 시간을 반영하는 시뮬레이션 계층
- 버스 단독과 철도-버스 복합 대안을 같은 조건에서 비교하는 실험 계층
- 반복 실행, 공통 난수, 민감도 분석으로 불확실성을 비교하는 분석 계층
- 지도, 표, 요약 문장으로 결과를 설명하는 의사결정 지원 계층
- LLM은 보고서 요약, 질의응답, 결과 설명 보조에 제한하고, 핵심 판단은 재현 가능한 수치 산출물에 둔다.

피해야 할 표현:

- "AI가 최적 작전안을 자동 산출한다"
- "실시간 전장 상황을 예측한다"
- "현장 배차를 자동 통제한다"
- "검증 완료된 작전 체계이다"

인수 조건:

- AI의 역할이 예측·최적화·민감도 분석·설명 보조로 구분되어야 한다.
- 시뮬레이션 결과와 LLM 생성 문장의 권한 차이가 명확해야 한다.

### 6.5 웹 데모 에이전트

목표는 보고서에 넣을 수 있는 안전한 데모 화면을 준비하는 것이다.

데모 지도 원칙:

- 지도를 공개 권역 단위로 추상화한다.
- 출발·환승·도착은 "서울/수서권", "철도 환승 축", "평택지제/평택 지원 권역"처럼 넓게 라벨링한다.
- 실제 작전 세부 경로처럼 보이는 정밀 선형, 세부 시각표, 민감 시설명은 넣지 않는다.
- 지도에는 "비작전 모의 예시", "공개자료 기반 의사결정 지원", "실제 배치 지침 아님" 문구를 표시한다.

필수 산출물:

- 데모 화면 사양서
- 지도 라벨 목록
- 범례 문구
- 비작전 주의 문구
- Vercel 배포 URL

인수 조건:

- Vercel URL이 실제 접근 가능해야 한다.
- 화면에 단일 시나리오 축만 보여야 한다.
- 스크린샷 캡처 전에 라벨과 주의 문구가 반영되어야 한다.

### 6.6 스크린샷 에이전트

목표는 보고서 삽입용 이미지를 재현 가능하게 캡처하는 것이다.

필수 캡처:

- 데모 첫 화면: 시나리오 축과 비작전 주의 문구가 함께 보이는 화면
- 대안 비교 화면: 버스 단독과 철도-버스 복합 대안 비교 표 또는 그래프
- 병목·위험 요약 화면: 위험 구간 또는 KPI 요약이 보이는 화면

스크린샷 매니페스트 항목:

- 파일명
- 캡처 URL
- 캡처 일시
- 화면 크기
- 포함된 라벨
- 보고서 삽입 위치
- 비작전 문구 포함 여부

인수 조건:

- URL과 스크린샷 파일이 모두 존재해야 한다.
- 스크린샷 안에 민감하거나 작전 지시처럼 보이는 정보가 없어야 한다.
- 스크린샷 삽입 전 보고서 문단에는 확정 파일명만 참조한다.

### 6.7 데모 문단 에이전트

목표는 URL과 스크린샷이 확정된 뒤 본문 문단을 작성하는 것이다.

작성 원칙:

- "아래 화면은 실제 배치 지침이 아니라 공공데이터 기반 모의 예시"라고 명시한다.
- URL은 데모 확인용으로만 제시한다.
- 지도는 실제 경로 지시가 아니라 대안 비교 인터페이스라고 설명한다.
- 스크린샷에서 보이는 KPI는 예시 결과이며 최종 승인 증거가 아니라고 적는다.

인수 조건:

- 데모 문단 안에 확정 URL과 확정 스크린샷 파일명이 들어가야 한다.
- URL이 없는 상태에서 "배포 완료"라고 쓰지 않는다.

### 6.8 주장 안전성 검토 에이전트

목표는 최종 제출 전 모든 문장이 비작전·비승인·비보장 원칙을 지키는지 확인하는 것이다.

검토 항목:

- 실제 작전 명령처럼 읽히는 문장
- 실제 경로·배차·시간표를 지시하는 문장
- 군 내부 데이터 보유 또는 검증 완료를 암시하는 문장
- 최종 수용, 현장 적용 가능, 성능 보장을 단정하는 문장
- 공개 출처가 없는 수치와 지명 표현
- 데모 화면이 작전 지도처럼 보이는 표현

수정 원칙:

- "산출한다"보다 "비교해 제시한다"를 우선한다.
- "추천 경로"보다 "대안별 위험 비교"를 우선한다.
- "운용 가능"보다 "시범 적용 가능성 검토"를 우선한다.
- "검증 완료"보다 "추가 검증 필요"를 우선한다.

인수 조건:

- 위험 표현 목록과 수정 결과가 남아 있어야 한다.
- 최종본에는 금지 표현이 없어야 한다.

## 7. 보고서 섹션별 작성 계획

### 7.1 아이디어명

후보:

- AI 기반 비상 수송 의사결정 지원 시뮬레이션
- AI-MOVE: 공공데이터 기반 비상 수송 대안 비교 체계
- 서울/수서-평택지제 축 비상 수송 의사결정 지원 AI

권장 제목:

> AI 기반 비상 수송 의사결정 지원 시뮬레이션

제목에는 실제 지역 축을 과도하게 드러내지 않고, 본문에서 단일 예시 시나리오로 설명한다.

### 7.2 제안 배경 및 목적

작성 포인트:

- 비상 상황에서는 도로 혼잡, 링크 장애, 환승 지연, 차량 회차 제약이 동시에 발생할 수 있다.
- 기존의 단일 경로 중심 검토는 대안별 실패 조건과 병목을 비교하기 어렵다.
- 공공데이터와 시뮬레이션 AI를 결합하면 실제 운용 전 단계에서 여러 대안을 빠르게 비교할 수 있다.
- 본 제안은 명령 체계가 아니라 참모 검토와 훈련, 사전 계획 검토를 보조하는 의사결정 지원 체계이다.

### 7.3 아이디어 요약

요약 구조:

- 입력: 공개 교통망, 철도 환승 축, 수요 규모 예시, 차량·환승 가정, 장애 시나리오
- 처리: 반복 시뮬레이션, 대안 비교, 병목 탐지, 민감도 분석
- 출력: 완료시간, 미수송 위험, 병목 요약, 정책 대안 비교표, 데모 지도
- 활용: 사전 계획 검토, 훈련 시나리오, 공공데이터 기반 확장, 참모 의사결정 보조

### 7.4 아이디어 상세 내용

세부 구성:

- 데이터 수집 및 정제: 공개 도로망·철도·행정구역 자료를 그래프와 권역 라벨로 변환
- 시나리오 설정: 서울/수서권에서 평택지제/평택 지원 권역까지의 단일 비작전 예시
- 수송 대안 설정: 버스 단독, 철도-버스 복합, 분산 출발 또는 예비 대안
- 모의 실행: 반복 실행으로 지연과 장애 조건을 반영
- AI 분석: 대안별 취약 조건, 민감 변수, 병목 지점을 자동 요약
- 결과 제시: 지도, 표, 그래프, 짧은 설명 문단으로 참모 검토 자료 제공

### 7.5 차별성

강조할 점:

- 일반 길찾기와 달리 장애, 지연, 수요 미도착, 회차 제약을 반영한다.
- 단일 정답이 아니라 대안별 위험과 취약 조건을 비교한다.
- 생성형 AI 설명을 수치 근거와 분리해 검증 가능한 구조로 둔다.
- 공공데이터 기반으로 시작해 폐쇄망·비식별 자료 연계를 단계적으로 설계한다.
- 실제 작전 지시가 아니라 사전 검토와 훈련용 판단 보조에 초점을 둔다.

### 7.6 실현 가능성

포함할 내용:

- Python 기반 시뮬레이션 파이프라인으로 구현 가능한 구조
- 도로·철도·환승·차량·수요·장애 모듈의 단계적 개발 가능성
- 공개자료 기반 MVP와 폐쇄망 확장형 운영 모델의 분리
- 검증 전에는 수치 결과를 예시로만 사용하고, 공식 적용 전 별도 검증이 필요하다는 한계
- Vercel 데모는 개념 시연용이며 실제 운용 체계가 아니라는 점

### 7.7 적용 효과성

작성 포인트:

- 대안별 병목을 사전에 찾을 수 있다.
- 제한된 차량·시간 조건에서 취약 정책을 비교할 수 있다.
- 훈련 후 평가나 사전 계획 검토에서 정량 근거를 제공할 수 있다.
- 공개자료 기반으로 여러 지역에 재사용 가능한 템플릿을 만들 수 있다.
- 군뿐 아니라 재난, 공공기관, 지방자치단체 비상 수송 계획에도 확장 가능하다.

### 7.8 추진 전략

단계별 로드맵:

1. 0~3개월: 공공데이터 기반 단일 시나리오 MVP
2. 3~6개월: 데모 지도, 결과 대시보드, 보고서 자동 요약
3. 6~12개월: 비식별 내부 자료 연계 검토, 훈련 데이터와 비교 검증
4. 12개월 이후: 지역 템플릿화, 폐쇄망 배포, 반복 훈련 평가 체계 연계

단계별 산출물:

- MVP 코드와 샘플 결과
- 데모 URL과 스크린샷
- 출처·가정값 행렬
- 안전성 검토 기록
- 검증 계획서

## 8. 출처 및 증거 관리 원칙

출처는 본문 하단 또는 별도 표에 정리한다.

필수 구분:

- 공식 공모 정보
- 공개 교통망 또는 지도 정보
- 공개 철도·역 관련 정보
- 프로젝트 내부 구현 근거
- 시뮬레이션 가정값
- 검증 전 보류값

증거 문구 규칙:

- 공식 출처에서 확인한 사항만 단정한다.
- 프로젝트 내부 결과는 "프로토타입", "예시 결과", "검토용 산출물"로 쓴다.
- 가정값은 "임의 설정" 또는 "시나리오 파라미터"로 표기한다.
- 현재 감사·수용 보조 패킷은 최종 승인 증거로 쓰지 않는다.

## 9. 데모 및 스크린샷 삽입 규칙

데모 관련 본문은 다음 조건이 충족된 뒤 작성한다.

- 웹 데모가 실제로 배포되어 URL이 확정됨
- 지도 라벨과 비작전 주의 문구가 화면에 반영됨
- 스크린샷 파일이 생성되고 삽입 위치가 정해짐
- 스크린샷 매니페스트가 작성됨

스크린샷 캡션 예시:

- "공개자료 기반 비작전 모의 예시 화면"
- "서울/수서-평택지제 축 대안 비교 데모"
- "실제 배치 지침이 아닌 의사결정 지원용 위험 요약 화면"

금지 캡션:

- "실제 수송 경로"
- "최종 배치안"
- "작전 적용 화면"
- "검증 완료 결과"

## 10. 수용 기준

보고서 초안은 다음 기준을 모두 만족해야 한다.

- 정확히 하나의 시나리오만 다룬다.
- 서울/수서권 및 평택지제/평택 지원 권역 표현이 넓은 권역 수준으로 유지된다.
- 실제 경로 지시, 작전 명령, 배차 지침으로 읽히는 문장이 없다.
- 공식 출처, 공개자료, 내부 가정값, 검증 전 보류값이 분리되어 있다.
- 데모 URL이 확정되기 전에는 데모 완료 문장이 없다.
- 스크린샷이 확정되기 전에는 스크린샷 설명 문단이 최종화되지 않는다.
- 주장 안전성 검토 결과가 최종본에 반영되어 있다.
- 최종 문서는 공모 평가 기준인 창의성, 실현 가능성, 적용 효과성, 완성도를 모두 직접 겨냥한다.

## 11. 최종 검증 체크리스트

제출 전 다음 항목을 순서대로 확인한다.

### 11.1 시나리오 검증

- [ ] 보고서 전체에 시나리오가 하나만 존재한다.
- [ ] 서울/수서권과 평택지제/평택 지원 권역 외 다른 실증 축이 추가되지 않았다.
- [ ] 세부 작전 경로, 실제 시간표, 실제 배차 지시가 없다.

### 11.2 출처 검증

- [ ] 공식 공모 정보 출처가 확인되어 있다.
- [ ] 공개 교통망·철도·지도 자료 출처가 구분되어 있다.
- [ ] 가정값과 공개자료가 분리되어 있다.
- [ ] 출처 없는 수치가 본문에서 단정형으로 쓰이지 않았다.

### 11.3 데모 검증

- [ ] 웹 데모 지도와 라벨이 단일 시나리오에 맞다.
- [ ] Vercel URL이 확정되어 있다.
- [ ] 스크린샷이 확정 URL에서 캡처되었다.
- [ ] 스크린샷 안에 비작전 주의 문구가 보인다.
- [ ] 데모 문단은 URL과 스크린샷 확정 이후 작성되었다.

### 11.4 주장 안전성 검증

- [ ] "작전 명령", "자동 배치", "실시간 통제", "검증 완료" 성격의 표현이 없다.
- [ ] 모든 결과는 의사결정 지원, 사전 검토, 모의 예시로 표현되어 있다.
- [ ] 최종 승인 증거처럼 보이는 감사·수용 관련 문장이 없다.
- [ ] 민감 시설명, 세부 동선, 세부 시간표가 없다.

### 11.5 제출 품질 검증

- [ ] 공모 양식의 주요 항목을 모두 채웠다.
- [ ] 평가 기준 네 가지가 본문에 자연스럽게 연결되어 있다.
- [ ] 그림·표·캡션이 본문 주장과 일치한다.
- [ ] 분량이 제출 제한 안에 있다.
- [ ] 문체가 과장 없이 구체적이다.
- [ ] 최종본 파일명, 데모 URL, 스크린샷 파일명이 서로 일치한다.

## 12. 최종 제출 전 결론 문장 방향

최종 보고서의 결론은 다음 방향으로 마무리한다.

> 본 제안은 실제 작전 명령을 자동화하는 체계가 아니라, 공공데이터와 시뮬레이션 AI를 활용해 비상 수송 대안의 위험과 병목을 사전에 비교하는 의사결정 지원 아이디어이다. 서울/수서-평택지제 축의 단일 비작전 예시를 통해 구현 가능성을 설명하고, 향후 검증·보안 검토·폐쇄망 적용을 거쳐 훈련과 계획 검토에 활용할 수 있는 단계적 발전 방향을 제시한다.
